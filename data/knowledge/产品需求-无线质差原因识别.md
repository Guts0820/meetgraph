# 市场需求文档摘要：无线质差原因识别算法

> 文档编号：REQ-2026-0417；版本：v1.3；负责人：产品部 陈静
> 说明：本文档只使用标准术语，缩写与别名以《内部术语表》为准。

## 业务场景

运营商在无线网络中出现业务质量下降时，网络优化人员需要在**2 小时内**给出原因判断，当前主要依赖人工经验，平均定位时长 **6.5 小时**，且结论难以复现。

本算法面向**用户体验质量**劣化的场景，输入为网络性能指标、**话单**与**路测**数据，输出为质差原因及其贡献度，供网络优化人员决策使用。

## 验收标准

1. 在试点局点的验证集上，**质差原因 Top-1 准确率不低于 75%**，Top-3 覆盖率不低于 92%；
2. 单小区单日推理耗时不超过 **3 分钟**（P95）；
3. 每条结论必须可解释：给出贡献度最高的前 3 个影响因素及其量化贡献；
4. 支持**质差原因体系**中的全部类别，不再新增未登记的原因类型。

## 场景与优先级

| 优先级 | 场景 | 说明 |
|--------|------|------|
| P0 | 视频类业务体验质差 | 卡顿率与启动时延为主要观测指标 |
| P1 | 语音类业务质差 | 接通率、掉话率 |
| P2 | 通用数据业务质差 | 速率与完整性 |

## 依赖与约束

- 数据依赖：**话单**与**路测**数据的接入需符合《数据接入规范》；
- 算法约束：结论需给出反事实意义上的归因（即「若该因素不存在，质差会缓解多少」），不接受仅有相关性的输出；
- 合规约束：不得使用用户号码等个人标识字段，统一做哈希化处理。
