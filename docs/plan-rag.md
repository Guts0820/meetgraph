# RAG 分步实施计划（会议历史 + 内部文档检索）

## 目标

给 MeetGraph 增加检索增强能力，解决两件真实的事：

1. **会议历史可检索**：会上有人说「上次谁定的这个 deadline」「Q3 预算讨论过几次」，系统能跨会议检索历史纪要并给出带引用的答案；
2. **内部文档 + 公司术语**：检索公司内部文档（需求文档、规章制度、术语表），并把**内部专业术语**用于三处——查询扩展、检索加权、生成约束，用评测证明业务准确率提升。

## 设计

```
内部文档(data/knowledge)/历史会议纪要 ──► 分块 ──► 向量索引(numpy) + BM25 倒排
                                                        │
用户问题 ──► 术语归一化/扩展 ──► 混合检索(向量+BM25, RRF) ──► 术语加权 ──► Top-K
                                                                          │
                                          上下文组装(术语表 + 引用要求) ──► LLM ──► 带引用答案
```

### 术语层的四个作用点

| 作用点 | 做什么 | 为什么 |
|--------|--------|--------|
| Query 扩展 | 「MRD 什么时候定的」→ 追加别名/全称「市场需求文档」再检索 | 缩写、内部黑话与文档用语不一致是检索失败主因 |
| 检索加权 | 命中术语的 chunk 加分 | 术语密度是内部文档相关性的强信号 |
| 生成约束 | 把命中术语的**标准定义**注入 prompt，要求使用公司术语、不得改写成近义词 | 降低「同一概念多种叫法」造成的业务误解 |
| 评测 | 术语类问题单独统计命中率，并做术语开/关 A/B | 提升要能量化，而不是感觉 |

### 关键实现选择（已按环境探测结果定）

- **不引入 sentence-transformers / jieba / faiss**：venv 已有 `transformers` + `torch`，直接用它加载 `BAAI/bge-small-zh-v1.5`（约 95MB）；中文分词用 CJK 二元切分（IR 常规做法），向量索引用 numpy 余弦（语料规模小，够用）。
- **HF 直连不通、镜像通**：下载模型需 `HF_ENDPOINT=https://hf-mirror.com`。
- **embedder 可插拔**：`HashingEmbedder`（离线确定性，测试用）/ `TransformersBgEmbedder`（本地真实模型）/ `OpenAICompatEmbedder`（可选 API），缺模型时自动降级为 BM25-only，测试与 CI 永不依赖网络。

## 执行中的偏差（实测推翻的两处设计）

| 原设计 | 实测结果 | 改成 |
|--------|----------|------|
| 「原查询 + 术语扩展词」拼成一个查询做检索 | Recall@1 从 0.625 掉到 0.417：扩展词稀释语义中心，术语表还靠密度抢首位 | 四路独立召回（向量通道只用原查询）+ RRF 融合 + 术语表条件降权 |
| 只做 RRF 融合，不做精排 | 同主题文档互相抢位，制度规范类 Recall@1 仅 0.125 | 增加确定性精排（查询词覆盖度 / 连续短语 / 小节标题 / 术语密度）→ 0.875 |

结论性发现：**术语层在语义通道存在时增益≈0，在无语义模型时才显著**（Recall@1 +4.1pt ~ +8.4pt）。完整数据与原因分析见 [evaluation.md](evaluation.md#五rag-检索评测scriptssevaluate_ragpy)。

## 评测口径

- **Recall@5 / MRR**：标注问答的期望来源是否出现在 Top-5；正确来源的排名倒数。
- **术语命中率**：术语类问题中，答案/引用是否覆盖期望术语。
- **术语 A/B**：同一套问题分别关闭/开启术语扩展与加权，比较 Recall@5 与 MRR 的差值（预期别名类问题显著提升）。
- **引用可核验率**：答案中的引用能否在索引里定位到原文（防幻觉的硬指标）。
- 真实 LLM 的答案质量另用 LLM-as-judge 评分（`--live`，可选）。

## 风险与兜底

| 风险 | 兜底 |
|------|------|
| HF 模型下载失败 | 自动降级为 BM25 + 术语扩展；评测分别报告向量通道是否可用 |
| 语料是构造的（非真实内部文档） | 语料与标注都放在 `data/knowledge/` 与 fixtures 里，README 明确说明「示例语料、可替换」；指标口径如实标注 |
| 中文分词质量 | CJK 二元切分对中文检索足够，且不引入依赖；后续可换 jieba 作对比实验 |
| 与主流水线耦合过深 | RAG 作为独立模块先可用（步骤 1–6），再以可选节点接入（步骤 7），失败时跳过检索不阻塞 Pipeline |
